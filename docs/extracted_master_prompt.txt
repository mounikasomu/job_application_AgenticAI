Base prompt:-  Master Foundational Prompt
Markdown
### TASK OVERVIEW
You are an expert full-stack AI engineer tasked with building an **AI Job Application Assistant with Application Tracker**. 

You will construct a four-tab, client-side web application driven by an LLM orchestration layer and local JSON state persistence. The system automates candidate profile setup, job description (JD) skill matching, tailored PDF resume generation, multi-stage application tracking, per-rejection AI feedback learning, and cross-rejection SWOT analysis.

---

ARCHITECTURE & DATA LAYER
1. Single Local Data Store
All application state MUST reside in a single local JSON file (e.g., app_data.json). 
No external database is permitted. 
JSON State Schema:
JSON
{
  "is_onboarded": false,
  "current_profile_state": {},
  "profile_update_history": [],
  "applications": [],
  "global_analysis": {}
}
Clear All Data Action: Include a persistent "Clear All Data" control in the global header. On double-confirmation, completely wipe the JSON file and reset all views to their initial empty states. 
2. Living Profile Core Engine
The system maintains an evolving candidate profile object (current_profile_state). 
The original document upload populates the baseline schema. 
Crucial Rule: Subsequent rejection analyses dynamically downgrade, refine, or update current_profile_state. All new JD match assessments and PDF resume generations in Tab 1 MUST consume this evolving state—not the static raw upload. 
FUNCTIONAL TAB SPECIFICATIONS
View 0: First-Run Onboarding Flow
Triggered if is_onboarded is false or data is cleared. 
Inputs: Mandatory Candidate Profile (.txt, .pdf, .docx) and Optional Reference Resume (.pdf, .docx). 
Parse unstructured upload into the target JSON structure (Name, Credentials, Summary, Skills, Projects, Work Experience, Extracurriculars, Achievements, Education).
Render an interactive UI editor allowing granular Add [+], Edit, and Remove [-] actions on every node before committing to current_profile_state.
Tab 1: Apply (Resume Prep & Submission Simulation)
Inputs: Paste Job Description (JD), extract Company Name, Role, Required Skills, Profile Skills, and calculate Skill Match % beyond basic keyword lookup (factoring in semantic relevance and experience context). 
Prepare Resume Button Activation: Disabled until candidate profile loaded, JD pasted, company name set, role set, skills extracted, and match % calculated. 
Resume Generation: Use Python ReportLab to produce a downloadable PDF. Mirror style/layout from the reference resume if provided. Adjust skill emphasis according to current_profile_state without exposing system flags or diagnostic terms. 
Submitted Button: Unlocks only after PDF download. Clicking logs the job application into Tab 2 with status Submitted (displaying a green blinking status indicator). 
Tab 2: Tracking (Application Tracker Table)
Display active applications: Company, Role, Skills, Match %, Viewable JD, Status, Action Buttons. 
Status Flow: Submitted  Interview  Selected OR Not Selected. 
Confirmation modal required if jumping directly to Selected without Interview. 
Direct Not Selected transitions prompt confirmation before removing the entry from Tab 2 and moving it to Tab 3. 
Tab 3: Not Selected (Rejection Analysis & Profile Learning)
Display rejected rows with a free-text Rejection Notes box (interview details, missed questions, rejection email content). 
Analyze Button: Trigger an LLM analysis evaluating skill gaps against the JD and notes. Automatically update current_profile_state in the JSON store and append to profile_update_history. 
Tab 4: Global Analysis (Cross-Rejection SWOT Report)
Aggregate data across all rejection rows in Tab 3. 
Require a minimum of 2 rejections to run; otherwise render a friendly empty state view. 
Generate a structured SWOT Analysis (Strengths, Weaknesses, Opportunities, Threats) paired with a warm, encouraging executive summary and 3 prioritized action items. 
ACCEPTANCE CRITERIA
The app executes smoothly across all 4 tabs and onboarding screens[cite: 1].
Styling strictly follows the specified color hierarchy and visual system.
Profile updates from Tab 3 rejections seamlessly propagate to subsequent Tab 1 match evaluations and ReportLab resume generations[cite: 1].
Application state updates cleanly inside local JSON storage without data loss[cite: 1].

### TASK OVERVIEW
You are an expert AI engineer building the initial onboarding and candidate profile setup flow for an AI Job Application Assistant. 

Implement a structured, multi-step profile onboarding interface with an LLM-powered document extraction pipeline that converts unstructured resume/profile uploads into an editable, schema-aligned candidate state saved to a local JSON file.

Follow up Prompt 2:-
### TASK OVERVIEW
You are an expert AI engineer building **Tab 4: Global Analysis** for the AI Job Application Assistant[cite: 1]. 

Expand the global analysis component beyond basic skill gap reporting into a holistic, structured **SWOT Analysis** (Strengths, Weaknesses, Opportunities, Threats)[cite: 1]. The objective is to evaluate cross-rejection patterns, highlight competitive advantages, pinpoint areas for growth, and provide an encouraging, actionable roadmap for the candidate[cite: 1].

---

### FUNCTIONAL REQUIREMENTS & SYSTEM FLOW

#### 1. Data Aggregation Input
* The Global Analysis engine must read across **all rejection entries** stored in the local JSON data store[cite: 1].
* Inputs consumed per rejection row[cite: 1]:
  * Targeted Job Description & Required Skills[cite: 1].
  * Initial Skill Match Score[cite: 1].
  * User-provided Rejection Notes & Interview Feedback[cite: 1].
  * Per-row AI Analysis & updated Candidate Profile state (`current_profile_state`)[cite: 1].

#### 2. Comprehensive SWOT & Intelligence Output
When the user visits Tab 4 or clicks **"Run Global Analysis"**, the LLM must generate a structured report organized into the following four distinct sections[cite: 1]:

* **💪 Strengths (Encouragement & Validation):**
  * Core technical and domain competencies that consistently match JDs across applications[cite: 1].
  * High-performing interview areas, strong project highlights, or skills where the candidate routinely scores high[cite: 1].
  * Positive reinforcement to maintain candidate motivation during the job search.

* **🎯 Weaknesses (Identified Skill & Experience Gaps):**
  * Recurring missing skills or tools identified across multiple rejections[cite: 1].
  * Frequently missed interview topics, question types, or weak domain knowledge[cite: 1].
  * Experience framing or structural resume gaps that require refinement[cite: 1].

* **🚀 Opportunities (Strategic Growth & Positioning):**
  * High-value tools, technologies, or concepts that—if learned—would unlock the highest percentage of targeted job roles.
  * Strategic tweaks to project framing, resume terminology, or interview prep focus areas[cite: 1].
  * Low-hanging fruit skills that bridge the gap to higher match percentages[cite: 1].

* **⚠️ Threats (Market & Domain Alignments):**
  * Systematic mismatches between the candidate's current experience level and targeted role seniorities[cite: 1].
  * Emerging industry trends or required toolsets in candidate's target roles that are currently absent from their profile[cite: 1].

#### 3. Strategic Summary & Action Plan
* **Plain-Language Executive Summary:** A warm, encouraging, grounded summary paragraph synthesizing the user's overall standing[cite: 1].
* **Top 3 Immediate Actions:** A numbered list prioritizing the exact three steps the candidate should complete before submitting their next batch of applications[cite: 1].

#### 4. Dynamic Empty State Handling
* If there are **fewer than 2 rejected applications** in Tab 3[cite: 1]:
  * Display a clean, encouraging Empty State view: *"Insufficient rejection data to generate cross-pattern insights. Complete rejection analyses in Tab 3 to unlock your comprehensive SWOT report."*[cite: 1]

---

### TECHNICAL & RUBRIC REQUIREMENTS
1. **Grounded Reasoning:** The analysis must strictly rely on aggregated rejection history and the living profile JSON state—preventing hallucinated or generic feedback[cite: 1, 2].
2. **Encouraging & Constructive Tone:** The framing must balance candid gap identification with motivating validation of candidate strengths[cite: 1, 2].
3. **JSON Storage Persistence:** Store the latest Global Analysis result object (including timestamp and SWOT model) directly in the local JSON file[cite: 1].

---

### ACCEPTANCE CRITERIA
* Displays an informative empty state when insufficient rejection data exists[cite: 1].
* Aggregates history across all rows in Tab 3 to produce a complete SWOT report[cite: 1].
* Highlights both positive candidate strengths and growth areas (weaknesses) to keep the user encouraged[cite: 1].
* Provides concrete, prioritized action steps for subsequent job applications[cite: 1].
